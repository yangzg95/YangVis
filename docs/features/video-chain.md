# 尾帧链式渲染（镜间画面物理连续）

解决「各分镜之间不连贯」：默认模式下每镜首帧是一次独立文生图，12 镜就是 12 次
独立抽卡，人物长相、场景细节、色调只靠提示词里的文字锚点弱约束。链式模式把上一镜
视频片段的**尾帧**作为下一镜的首帧输入，相邻镜头共享同一帧画面，镜间衔接从「提示词
自觉」变成「物理连续」。

与 TTS 配音（[video-tts.md](video-tts.md)）是两条正交的链路：链式管画面连续性，
TTS 管声音，两者可同时开启，互不影响。

## 用户可见行为

- 工作台「渲染参数」新增开关「尾帧链式衔接」（项目级，存 `video_project.params.chain_clips`，
  默认关）。关闭时每条片段仍是互相独立的生成，行为与上线前完全一致。
- 开启后片段按镜头顺序渲染：同项目内一次只有一条视频作业能提交，后面的镜头停在
  「排队中」，工作台显示「等待第 N 镜」而不是干巴巴的排队。
- **严格模式**：参与渲染的镜头必须都是「首帧生视频」。t2v / 参考图模式没有可替换的
  首帧输入，入队即拒，文案点名镜号引导改回。
- 必须按顺序来：渲镜 3 要求镜 2 已有带尾帧的成功片段，否则入队被拒（部分渲染也按
  项目叙事顺序找紧邻前镜，不是选中集合里的前一个）。项目第一镜是链头，仍用它自己
  的首帧定调。
- 上游失败会链式阻断：镜 2 失败/取消/超时，镜 3 的作业自动判失败（`ChainBroken`），
  错误里点名镜号；修好镜 2 重渲后再重渲后续镜头即可，不会静默出半成品。
- 「参考上一版」重做（`reference_previous`）与链式互斥：显式重做动作优先，开启时
  链式让位，走原来的参考视频链路。
- 重做单镜不影响已入队的下游：chain 快照的是上镜**当时那条作业 id**，上镜重做产生
  新作业后，旧下游仍接旧尾帧；重新渲下游时才会接到新尾帧。

## 关键取舍

### 为什么用尾帧而不是首帧参考链

文生图多图参考（把上镜首帧当参考图传给出图）只能约束「长得像」，尾帧传递约束的是
「从哪个画面接着动」——后者直接消灭硬切点的画面跳变，是连贯感的主要来源。方舟视频
任务成功时本来就随片返回 `last_frame_url`，客户端早已在解析（`ark.TaskState`），
这套机制只是把这条没用上的数据线接上。

### 为什么串行是可接受的代价

并发渲染的前提是作业之间无依赖，链式恰好引入了逐镜依赖，同项目内并发度天然降为 1。
不同项目之间仍共享账号级的两个在途位子，互不阻塞。等待中的作业不占位子、不耗
attempts、不发任何请求，只是每轮 tick 被依赖门跳过。

### 为什么尾帧缺失时下游继续等而不是判死

部分型号或模式可能不返回尾帧。普通作业没有尾帧不算失败（视频本身是成功的），只有
链式下游真的等它时才构成问题——所以入队预检先拦一道（要求前镜成功且有尾帧），运行期
依赖门再兜一道（尾帧列空就继续排队），把「切换开关/换型号」的人工补救窗口留给用户，
而不是把一串作业判死。

### chain 快照为什么要在入队循环之前预算

入队循环会把新作业 id 回写到 `video_shot.video_job_id`，而镜头对象在 session 身份映射里
是同一实例：循环内再读「前镜指针」，读到的是刚入队的新作业而不是它上一版成功片段。
`chain_plans` 在循环前一次性预算并固定 `prev_job_id`，与 `publish_job.sources` 的
快照哲学一致。

## 实现结构

| 位置 | 职责 |
| --- | --- |
| `media_job.last_frame_rel_path` | 尾帧转存路径（新列，bootstrap 幂等 ALTER，零手工 DDL） |
| `services/media/jobs.py` `_store_last_frame` | 视频成功的同一 tick 内下载尾帧并落盘（24h 失效，不能延迟）；失败只告警不影响视频成功态 |
| 同文件 `_apply_chain_gate` | tick 提交门：上游在途则跳过、上游终态失败则判 `ChainBroken`/`ChainPrevMissing`、尾帧就绪才放行 |
| 同文件 `_inject_chain_frame` | 提交前把作业 `images` 整体替换为上镜尾帧（role=first_frame），打 `injected` 标记持久化，重启不重复替换 |
| `services/videos/service.py` `render_clips` | 开关解析、严格模式校验、前镜尾帧预检、`chain_plans` 预算与 `request.chain` 快照 |
| `models/schemas.py` | `VideoParams.chain_clips`；`MediaJobOut.chain_wait_shot` 透出等待镜号 |
| 前端 `VideoWorkbench.vue` | 链式开关、queued 作业显示「等待第 N 镜」 |

## 测试

- `test_media_jobs.py`：尾帧随片转存（视频 mp4 + 尾帧 png 各下载一次）、gate 三态
  （在途等待/就绪放行/上游失败传播/作业行消失/无尾帧继续等）、注入后请求体 images
  被尾帧整体替换且 `injected` 落库、普通作业绕过 gate 行为不变。
- `test_videos.py`：chain 快照指向旧作业且链头无 chain、缺尾帧拒绝、严格模式拒绝
  t2v、开关关闭无 chain 块、与参考上一版互斥、部分渲染按项目顺序找前镜。
