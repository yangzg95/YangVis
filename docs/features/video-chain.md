# 镜间衔接：同场景链式、转场与画面运动

解决两类观感问题：**不同分镜之间衔接太明显**（硬切 + 每镜独立抽卡），以及**画面里
太多静止段落**（台词太短、运镜写成「镜头固定」、片段本身近乎静帧）。

默认模式下每镜首帧是一次独立文生图，12 镜就是 12 次独立抽卡，人物长相、场景细节、
色调只靠提示词里的文字锚点弱约束；相邻镜头之间是一次硬切。这里做三件事：

1. **同场景链式**：场景标识相同的相邻镜头，把上一镜视频片段的**尾帧**作为下一镜的首帧
   输入，镜间画面物理连续。
2. **合成侧转场与运动兜底**：拼接时逐镜淡出/淡入，并对「近乎静帧」的片段加递进式
   缓推，配音按 J-cut 提前进画。
3. **脚本侧约束**：台词字数与镜头时长挂钩，`video_prompt` 必须写清动作、镜头位移与
   结束状态（见 [video-tts.md](video-tts.md) 的槽位口径）。

与 TTS 配音（[video-tts.md](video-tts.md)）是两条正交的链路：链式管画面连续性，
TTS 管声音，两者可同时开启，互不影响。

## 用户可见行为

- 工作台「渲染参数」的开关叫「同场景自动衔接」（项目级，存
  `video_project.params.chain_clips`，**默认开**）。关闭时每条片段仍是互相独立的生成。
- 逐镜判定，不是整批模式：只有**相邻**两镜的 `scene_key`（分镜行「场景标识」字段）
  一字不差相同、且当前镜是「首帧生视频」时，这一镜才接上一镜尾帧。标识不同、标识为
  空、或当前镜是 t2v/参考图模式 → 这一镜按自己的首帧正常渲染，**不拦、不报错**。
  存量镜头没有标识，行为与改造前一致；要衔接就补标识或重新生成脚本。
- 项目第一镜是链头，仍用它自己的首帧定调。
- 衔接成立时片段按镜头顺序渲染：同项目内一次只有一条视频作业能提交，后面的镜头停在
  「排队中」，工作台显示「等待第 N 镜」而不是干巴巴的排队。
- 上游失败会链式阻断：镜 2 失败/取消/超时，镜 3 的作业自动判失败（`ChainBroken`），
  错误里点名镜号；修好镜 2 重渲后再重渲后续镜头即可，不会静默出半成品。上游作业行被
  删掉则判 `ChainPrevMissing`，同样提示重渲这一镜。
- 「参考上一版」重做（`reference_previous`）与链式互斥：显式重做动作优先，开启时
  链式让位，走原来的参考视频链路。
- 重做单镜不影响已入队的下游：chain 快照的是上镜**当时那条作业 id**，上镜重做产生
  新作业后，旧下游仍接旧尾帧；重新渲下游时才会接到新尾帧。
- 合成交付不再是一串硬切：镜间 0.3 秒淡出/淡入，配音比画面切点提前 0.2 秒进画。

## 关键取舍

### 为什么按 `scene_key` 逐镜判定，而不是整批开关串行

尾帧传递约束的是「从哪个画面接着动」，跨场景接会把会议室的尾帧拖进街头镜头——那比
硬切更糟。连续镜头（同一段对话拆成两镜）需要衔接，空镜插入、换场则本就该切。场景
标识由分镜师按 [agents.py](../../backend/app/services/agents.py) 的 video-storyboarder
第 15 条规则产出（4-12 字短名词，相邻同场景必须一字不差），工作台可手改，所以判定
单位只能是「相邻这一对」，不能是「这个项目」。

### 为什么接不上时不报错

标识为空、前镜还没渲成功、前镜是 t2v 档——这些都是**存量项目的常态**而不是用户错误。
早先的严格模式（整批要求首帧档 + 前镜必须已有带尾帧的成功片段）会让「打开开关」变成
一次批量拒绝，用户第一次点渲片段就被文案教育。现在只有一种情况报错：链已经成立、
上游随后死了（`ChainBroken`），因为这时不拦就会拼出一条没接上的半成品。

### 为什么用尾帧而不是首帧参考链

文生图多图参考（把上镜首帧当参考图传给出图）只能约束「长得像」，尾帧传递约束的是
「从哪个画面接着动」——后者直接消灭硬切点的画面跳变，是连贯感的主要来源。方舟视频
任务成功时本来就随片返回 `last_frame_url`，客户端早已在解析（`ark.TaskState`），
这套机制只是把这条没用上的数据线接上。

### 为什么串行是可接受的代价

并发渲染的前提是作业之间无依赖，链式恰好引入了逐镜依赖，同场景段内并发度降为 1。
不同项目之间仍共享账号级的两个在途位子，互不阻塞。等待中的作业不占位子、不耗
attempts、不发任何请求，只是每轮 tick 被依赖门跳过。

### 为什么尾帧缺失时下游继续等而不是判死

部分型号或模式可能不返回尾帧。普通作业没有尾帧不算失败（视频本身是成功的），只有
链式下游真的等它时才构成问题——所以入队时前镜缺尾帧就不建链（这一镜渲自己的），运行期
依赖门再兜一道（尾帧列空就继续排队），把「补标识/换型号」的人工补救窗口留给用户，
而不是把一串作业判死。

### chain 快照为什么在作业循环里现取

入队循环会把新作业 id 回写到 `video_shot.video_job_id`，而镜头对象在 session 身份映射里
是同一实例：循环前预算拿到的「前镜指针」是它上一版**成功片段**，同批重渲时下游会接旧
产物。改为循环内现取——同批刚入队的前镜作业优先，库里指针兜底。

### 转场为什么是 dip-to-black 而不是叠化

线上 ffmpeg 是 `imageio-ffmpeg` 自带的 **4.2.2**，没有 `xfade`。两镜叠化需要先把每镜
各自带淡入淡出再 `concat`，代价是画面中段被削，而 0.3 秒的黑场过渡在竖屏短视频里
正是常见的段落标点，效果足够且没有版本要求。

### 运动兜底为什么先进 2× 再出目标尺寸

`zoompan` 的位移量按输出像素取整。直接 720×1280 输出时，0.05 的放大增量摊到每帧不到
一个像素，抽帧看仍是相同帧；先把画面放大到 2× 再缩回目标尺寸，位移才保得住。逐镜
`offset` 递进（`VIDEO_MOTION_ZOOM` 按镜号累加）保证相邻镜头的起始构图不同，运镜方向
看起来也在走。

### 配音为什么要提前进画

画面切到下一镜时声音才起，是最「PPT」的节奏。J-cut 把除第一句外的每句整体提前
`VIDEO_AUDIO_LEAD_S`，切点落在下一句语音内部，观众先听见再看见。实现上不能
`adelay + amix`（4.2.2 等 EOF 卡死），只能用首句槽位尾部扣掉提前量、后续句子整体前移
的串拼口径，详见 [video-tts.md](video-tts.md)。

## 实现结构

| 位置 | 职责 |
| --- | --- |
| `video_shot.scene_key` | 相邻同场景标识（新列，`String(64)`，bootstrap 幂等 ALTER，空串=未填即不衔接） |
| `media_job.last_frame_rel_path` | 尾帧转存路径（新列，同样幂等 ALTER） |
| `services/media/jobs.py` `_store_last_frame` | 视频成功的同一 tick 内下载尾帧并落盘（24h 失效，不能延迟）；失败只告警不影响视频成功态 |
| 同文件 `_apply_chain_gate` | tick 提交门：上游在途则跳过、上游终态失败判 `ChainBroken`/`ChainPrevMissing`、尾帧就绪才放行 |
| 同文件 `_inject_chain_frame` | 提交前把作业 `images` 整体替换为上镜尾帧（role=first_frame），打 `injected` 标记持久化，重启不重复替换 |
| `services/videos/normalize.py` | `shots_from_model` 产出 `scene_key`（裁 64 字符）；`fit_duration_s` 把台词字数换算成不低于的镜长（`SHOT_MAX_S` 封顶，只抬不压） |
| `services/videos/service.py` `render_clips` | `chain_source` 逐镜判定衔接对象、`chain_plan` 按前镜作业实况决定是否带 chain 块、同批新作业优先的快照 |
| `services/publish/composer.py` | `probe_size` + `_styled_filter`（淡入淡出 + 递进 `zoompan`）+ `_concat_styled`；`build_voiceover` 的 J-cut 槽位口径 |
| `services/agents.py` | video-storyboarder 第 4 条（台词字数↔时长）、第 7 条（动作/镜头位移/结束状态）、第 15 条（`scene_key`）与 JSON 样例 |
| `app/config.py` | `VIDEO_TRANSITION_S` / `VIDEO_MOTION_ZOOM` / `VIDEO_AUDIO_LEAD_S` / `VIDEO_COMPOSE_FPS` |
| `models/schemas.py` | `VideoParams.chain_clips`（默认 True）；`VideoShotOut/In.scene_key`；`MediaJobOut.chain_wait_shot` 透出等待镜号 |
| `frontend/src/api/videos.ts` | `VideoShot/VideoShotInput.scene_key` 显式声明：后端 `shotsFromModel` 整体替换分镜行，漏字段等于重新生成脚本时清空标识 |
| 前端 `VideoWorkbench.vue` | 「同场景自动衔接」开关与说明、分镜行「场景标识」输入与提示、queued 作业显示「等待第 N 镜」 |

## 测试

- `test_media_jobs.py`：尾帧随片转存（视频 mp4 + 尾帧 png 各下载一次）、gate 三态
  （在途等待/就绪放行/上游失败传播/作业行消失/无尾帧继续等）、注入后请求体 images
  被尾帧整体替换且 `injected` 落库、普通作业绕过 gate 行为不变。
- `test_videos.py`：同批相邻同场景串行衔接、跨场景不接、标识为空不接、前镜成功但无尾帧
  不接、前镜失败/取消不接、t2v 档不接、`chain_clips=false` 整批不接、默认参数即衔接、
  部分渲染按项目顺序找紧邻前镜且快照指向同批新作业、与「参考上一版」互斥；
  `scene_key` 保存与详情回读、normalize 裁长度与台词↔时长换算（含纯标点不计字数）。
- `test_publish_compose.py`：`_styled_filter` 的滤镜图断言（ interior 镜尾淡出+下镜淡入、
  逐镜 `zoompan` 递进 offset、`motion_zoom=0` 时只留信箱不写 fade）、真实编码阶段带
  转场入参、单镜也有运动兜底；`build_voiceover` 首句之后的每句整体提前、首句槽位只扣掉
  提前量不扣两份。既有 amix 卡死回归用例保持不变。
- 真实 ffmpeg 端到端复验（非用例）：转场+运动兜底拼接产物近重复帧 9→1、每镜尾部运动量
  非零；配音轨总时长 30.32s 无卡死，镜边界落在下一句语音内部 0.01-0.19s。
